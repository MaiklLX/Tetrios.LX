# CHECKPOINT 338 — аудит конфликтов desktop CSS

Дата: 2026-11-02  
Репозиторий: `MaiklLX/Tetrios.LX`  
Базовая версия: `main` (после публикации Checkpoint #337, commit `00836c80a5bc81f8e43798e535f9b0d3b281e16a`)  
Рабочая ветка: `audit/desktop-css-isolation`

## Цель
Остановить накопление конкурирующих CSS-слоёв в ПК-веб-версии и перейти к одной понятной настольной системе оформления, не меняя мобильную версию и игровую логику.

## Подтверждённые источником конфликты
1. В `site/index.html` сохранён большой встроенный блок `#bb-desktop-restoration-recovered-322`. Он повторно задаёт desktop-геометрию для `.app`, `.topbar`, экранов кампании, магазина, героев, ежедневного вызова и игрового поля.
2. В `site/desktop-shell.css` после него подключена новая система Desktop Shell V1 / Arena V1. Следовательно, стили одной и той же области определяются из двух независимых мест.
3. Для `#game .playlayout`, `#game .boardframe`, `#game .board` существуют разные поколения правил с разными колонками, ширинами и высотами. Последний старый inline-блок способен перебивать новую арену за счёт `!important`.
4. Встроенные стили `index.html` содержат множество исторических экранных и тематических правил. Некоторые относятся к мобильной карте кампании и не должны удаляться без разделения по назначению и breakpoint.
5. Поэтому дальнейшее добавление компенсирующих правил в конец CSS не является безопасным способом исправления.

## Следующий безопасный план
- Составить карту всех CSS-источников: встроенные style-блоки, внешние таблицы, динамические style-элементы, desktop media queries и повторяющиеся селекторы.
- Разделить правила на три группы: общие/мобильные, desktop-only, тематические/компонентные.
- Перенести только подтверждённые desktop-only правила в единую настольную таблицу и убрать их старые дубли из источника.
- Установить единый корневой desktop-контейнер и единое правило видимости экранов; каждый экран должен иметь собственную независимую геометрию.
- Удалять legacy-правила по одному экрану за проход: сначала меню и общая оболочка, затем кампания, ежедневный вызов/календарь, магазин, герои, настройки и арена.
- Проверять после каждого шага: мобильные стили не изменились; все экраны используют существующие DOM/JS hooks; три режима campaign/rogue/daily доступны; CSS braces и подключения корректны.
- Только после аудита каскада переходить к визуальной перестройке. Не добавлять новые override-слои поверх старых.

## Жёсткие ограничения
- Не менять игровую логику, обработчики, canvas drawing, localStorage, прогресс, данные, игровые режимы и ассеты.
- Не менять правила мобильной версии: все изменения настольной геометрии ограничивать `@media (min-width: 901px)`.
- Не удалять стили кампании/космоса и мобильные исправления только потому, что они находятся в `index.html`; сначала доказать, что это desktop-дубль.
- Не заявлять о визуальной проверке браузером, если она фактически не выполнена.
