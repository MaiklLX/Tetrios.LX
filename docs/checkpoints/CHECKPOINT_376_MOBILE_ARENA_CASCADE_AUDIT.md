## Что проверено после #375

1. Исходный 2D canvas имеет intrinsic-размер `300 × 690`, то есть каноническое соотношение **10:23**.
2. Реальный DOM создаёт `.gameleftcol` перед исходной колонкой арены. Поэтому мобильная сетка должна выбирать арену по исключающему селектору `:not(.gameleftcol):not(.sidecol)`, а не через `:first-child`. Это уже закреплено в #374.
3. 3D-слой использует класс `.bb-arena-canvas` и размещается поверх той же рамки абсолютным позиционированием. В #375 для портретных телефонов рамка, 2D canvas и 3D overlay получают одну геометрию.
4. В исходном CSS действительно сохранились более ранние правила с пропорцией 1:2 и прежними формулами высоты. Они расположены раньше мобильных исправлений #374/#375; для портретных телефонов до 520 px итоговые правила #375 идут последними и переопределяют их.
5. Десктопные правила отделены медиазапросом от 901 px. Новые изменения в #373–#375 не затрагивали принятый desktop baseline.

## Результат

- Не обнаружено основания менять DOM или игровую логику.
- Не добавлялись новые конкурирующие правила размеров: дальнейшее наращивание CSS без визуальной проверки создало бы ещё один слой конфликтов.
- Текущая ветка остаётся изолированной от `main`.
- GitHub Actions `Android WebView source audit` для head-коммита #375 завершился успешно.
- GitHub Pages workflow запускается только при push в `main`; PR #48 не опубликован и не имеет отдельного live-preview. Поэтому текущий результат нельзя честно выдавать за проверенный на реальном телефоне.
